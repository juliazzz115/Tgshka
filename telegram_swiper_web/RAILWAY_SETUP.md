# 🚂 Деплой на Railway.app

## Быстрая инструкция

### 1. Подготовка репозитория

Убедитесь, что все файлы закоммичены:
```bash
git add .
git commit -m "Подготовка к деплою на Railway"
git push
```

### 2. Создание проекта на Railway

1. Зайдите на https://railway.app
2. Войдите через GitHub
3. Нажмите **"New Project"**
4. Выберите **"Deploy from GitHub repo"**
5. Выберите ваш репозиторий `Tgshka`
6. Railway автоматически определит Python и начнет деплой

### 3. Настройка переменных окружения (опционально)

Если хотите задать API ключи заранее:

1. Перейдите в Settings проекта
2. Нажмите **Variables**
3. Добавьте (не обязательно, можно настроить через веб-интерфейс):
   - `TELEGRAM_API_ID` = ваш API ID
   - `TELEGRAM_API_HASH` = ваш API Hash

### 4. Проверка деплоя

1. Railway покажет логи билда
2. После успешного деплоя вы получите URL типа:
   ```
   https://your-app.up.railway.app
   ```
3. Откройте URL в браузере
4. Введите API ID и API Hash в веб-интерфейсе
5. Авторизуйтесь и начинайте работу!

## Структура файлов для Railway

Вот файлы, которые Railway использует:

- **`Procfile`** - команда запуска приложения
- **`requirements.txt`** - Python зависимости
- **`runtime.txt`** - версия Python
- **`railway.json`** - настройки билда и деплоя

## Важные моменты

### Порт
Приложение автоматически использует переменную окружения `PORT` от Railway.

### База данных
SQLite база данных сохраняется на диске Railway. При каждом деплое данные могут сбрасываться.

Для постоянного хранения данных рекомендуется:
- Добавить PostgreSQL плагин в Railway
- Обновить код для работы с PostgreSQL

### Session файлы
Telegram session файлы сохраняются локально. При каждом новом деплое придется авторизовываться заново.

**Решение:** добавьте PostgreSQL и храните session в БД.

### Логи
Смотрите логи в реальном времени в Railway Dashboard:
1. Откройте проект
2. Нажмите на deployment
3. Выберите вкладку **"Logs"**

## Troubleshooting

### Ошибка при установке cryptg

Если возникает ошибка с `cryptg`, это нормально. Telethon будет работать без него (просто немного медленнее).

### Application failed to respond

Убедитесь, что:
1. Приложение слушает на `0.0.0.0`, а не `localhost`
2. Используется правильная переменная `PORT`
3. В логах нет ошибок импорта

### Постоянная переавторизация

Telegram session не сохраняется между деплоями. Решения:
1. Не делать деплой часто
2. Использовать PostgreSQL для хранения session
3. Использовать постоянный том (persistent volume) в Railway
